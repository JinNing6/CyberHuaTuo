# 本地物理网络与OS层终极调优指南（脱离代理环境）

在讨论任何代理层面的“魔法”之前，你的本地主机——Windows 11与物理网卡（NIC）本身必须被武装到牙齿。大多数用户的网卡出厂设置是为了“省电”和“兼容老旧路由器”，这对于你的高频操作、瞬时吞吐量和极致低延迟是一种巨大的拖累。

以下是针对纯本地网络质量（速度、稳定性和延迟）的主理人级别深度优化操作。

## 第一重：网卡核心硬解（卸载 CPU 压力，解放网卡算力）
现在的网卡（如 Intel AX211/Killer 系列）内部都有独立的芯片，但系统默认会让 CPU 去处理很多本该由网卡处理的脏活累活。我们需要强制开启硬件卸载（Hardware Offload）。

打开 **设备管理器** -> 展开 **网络适配器** -> 右键你的主力网卡（WiFi或网线口）选择 **属性** -> 点击 **高级 (Advanced)** 选项卡：

1. **启用接收侧缩放 (Receive Side Scaling - RSS)**
   - **操作：** 找到 `Receive Side Scaling`，设置为 `Enabled`。
   - **原理：** 未开启时，所有巨大的网络流量（如下载几十GB模型、看高码率视频）处理工作只会压在 CPU 的唯一一个核心（通常是 Core 0）上，容易造成瞬时卡顿。开启 RSS 后，网卡会自动将流量分发给 CPU 的多核处理，这是提升本地多线程下载性能的最关键一步（注意：同时去 PowerShell 确认开启：执行 `netsh int tcp set global rss=enabled`）。
2. **启用大数据包发送卸载 (Large Send Offload - LSO v2)**
   - **操作：** 找到类似 `Large Send Offload Version 2 (IPv4)` 和 `(IPv6)`，设置为 `Enabled`。
   - **原理：** 让网卡芯片自己去负责把大块数据“切碎”成网络能传输的标准包（MTU），而不是用 CPU 切好再给网卡。
3. **启用校验和卸载 (Checksum Offload)**
   - **操作：** 找到 `TCP Checksum Offload (IPv4)` 和 `UDP Checksum Offload (IPv4)` 等选项，全部设置为 `Rx & Tx Enabled`。
   - **原理：** TCP/UDP 数据包不管发送还是接收，都要进行完整性数学校验。把这个计算过程完全扔给网卡底层的 DSP 芯片硬算，大幅降低延迟。

## 第二重：斩断一切“系统级妥协”
Windows 11 默认的某些“好心”机制，在高性能追求者看来就是毒药。

1. **粉碎节能限制 (Energy Efficient Ethernet / EEE)**
   - **操作：** 在刚刚的**高级**选项卡中，找到 `Energy Efficient Ethernet` (节能以太网)、`Green Ethernet` (绿色以太网)、`Idle Power Down` 等选项，**全部修改为 `Disabled`（禁用）**，如果是 WiFi，把“MIMO 节能模式”选为“无动态 SMPS”。
   - **原理：** 这些协议要求网卡在流量小的时候主动“睡过去”，有数据了再“唤醒”。这种毫秒级的唤醒延迟对于实时数据流和瞬时 API 请求是致命的断流根源。
2. **关闭中断裁决 (Interrupt Moderation) —— 极致低延迟的选择**
   - **操作：** 如果你追求的是如同动作游戏般的极致 API 响应速度（毫秒级必争），找到 `Interrupt Moderation` 并设为 `Disabled`。如果是追求下载大文件速度，可以保持开启。
   - **原理：** 开启时，网卡会“攒一波”数据再集中上报 CPU；关闭后，网卡每收到一个 bit 都会立刻“捅”一下 CPU，这会导致 CPU 使用率微升，但能换取最低的单包延迟。
3. **关闭 QoS 数据包计划程序**
   - **操作：** 按 `Win+R` 输入 `ncpa.cpl` 打开网络连接 -> 右键你连接的网络选“属性” -> **取消勾选** `QoS 数据包计划程序`。
   - **原理：** 阻止 Windows 以操作系统级别克扣你的带宽（Windows 默认会预留高达 20% 带宽给系统升级和后台服务）。

## 第三重：重构操作系统 TCP 神经元 (OS 核心参数越权重写)

从你反馈的当前 `netsh interface tcp show global` 默认参数来看，Windows 11 依然处于一种“温室里”的平衡妥协状态。既然我们要“一统全球资金与算力资源”，那就必须以最高权限，将所有为了“通用设备兼容性”而牺牲速度的赘余机制，在底层统统斩断。

1. **以管理员身份打开 PowerShell**。
2. 依次输入以下“主理人级”维度提权指令：

*   **1. 开启最强激进窗口调节 (Auto-Tuning Level: experimental)**
    *   **指令：** `netsh int tcp set global autotuninglevel=experimental`
    *   *说明：* Windows 默认的 `normal` 过于保守。这把锁一旦打开为 experimental，在面对远端大流量文件（或是模型权重）时，OS 会近乎贪婪地去吃满你的物理带宽极限，直到路由器崩溃为止。若当地运营商设备太拉垮导致降速，可用 `normal` 找回。
*   **2. 关闭接收段合并 (Receive Segment Coalescing / RSC: disabled)**
    *   **指令：** `netsh interface tcp set global rsc=disabled`
    *   *说明：* 重点打击对象！你现在的状态是 `enabled`。RSC 机制会在接收数据时，“等一等”，把几个小包合并成一个大包再给 CPU，这会导致几毫秒的粘包停顿。果断将其 Disable，换取最纯净的零延迟响应（特别是在使用基于 UDP/QUIC 代理时）。
*   **3. 启用谷歌 BBR2 拥塞控制引擎 (维度武器)**
    *   **指令：** 
        `netsh int tcp set supplemental template=internet congestionprovider=bbr2`
        `netsh int tcp set supplemental template=datacenter congestionprovider=bbr2`
    *   *说明：* 既然要追求极致，我们就绕过传统的妥协方案，直接强行注入 Google 专为跨国和高丢包网络设计的 BBR2 算法。这会让 Windows 在面对海外节点时，不再因为轻微丢包而疯狂降速，而是像水流一样强行填满你所有的屋里带宽。
    *   **指令：** `netsh interface tcp set heuristics disabled`
    *   *说明：* 制止 Windows 自作聪明地在后台反复“测试”连接状态从而偷偷修改配置，强行锁死我们上述配置的最大爆发模式。

## 架构师的诊断视角
真正的高手在执行上述操作后，不会去“凭感觉”判断是否有效。你可以随时打开“任务管理器（Ctrl+Shift+Esc）” -> 去到“性能”选项卡 -> 查看网卡。
当你下载百兆大文件时，如果你发现 CPU 各大核心负载均匀，且下载曲线平滑无锯齿断流，这就是一个被你**彻底解除了物理与协议封印**的纯血网络底座。

这三大维度的优化，是任何高级代理（梯子）发挥出超群实力的绝对前置条件。纯净的肉体（本地网卡驱动）才能承载最狂暴的思想（加密协议）。
