## Phase 0: 种子数据 & 仓库基建（3-4 周）

- [ ] 编写 JSON Schema（`schema/case.schema.json`）
- [ ] 开发 `tools/validate.py` 格式校验脚本
- [ ] 开发 `tools/new-case.py` 病例生成脚手架
- [ ] 开发 `tools/search.py` 本地搜索工具
- [ ] 配置 GitHub Actions CI 校验
- [ ] 编写 `CONTRIBUTING.md` 贡献指南
- [ ] 创建 Issue 模板和 PR 模板

### Week 3-4: 种子数据

- [ ] 从 LangChain GitHub Issues 采集整理 20 个高频问题

### 长期愿景

```
CyberHuaTuo 的终极形态 =
  AI 生态的「问题解决基础设施」

每个 AI 框架的文档里都会写:
  "遇到问题？去 CyberHuaTuo 查一下"

每个 AI 开发者的工具链里都有:
  pip install cyberhuatuo

就像 OpenClaw 让每个人共享 Agent 能力,
CyberHuaTuo 让每个人共享 AI 避坑指南。
不限框架，不限形态——只要是 AI，华佗都看。
```

## 风险与应对

| 风险 | 概率 | 应对策略 |
|------|------|---------  |
| 冷启动无人贡献 | 中 | 先灌高质量种子数据 + 降低贡献门槛 |
| 数据质量不齐 | 中 | CI 自动校验 + PR Review 把关 |
| 竞品出现 | 低 | 先发优势 + 数据积累 + 社区粘性 |
| 框架更新过快 | 高 | 版本标注系统 + 社区持续更新 |
